The join nobody owns

one order, four systems, no shared key

A refund knows its payment_id. A chargeback knows an ARN and a masked card tail, and nothing else. A support credit knows whatever the agent typed. These are the same order. No SQL join reaches across them, which is why the second payout leaves unnoticed.

The gate shows its arithmetic

The decision to hold a payout is expected value in rupees, not a score. It has to be, because the merchant will be asked why. A false positive here manufactures the very chargeback it was preventing. A wrongly-held refund escalates about 35% of the time, so that cost sits inside the arithmetic rather than in a footnote.

right-censoring, not noise
